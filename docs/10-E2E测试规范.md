# 🧪 E2E 测试规范

**最后更新**: 2026-05-09（§4.6 新增点击高亮）

## 核心原则

> **禁止在测试中使用依赖语言的文本定位元素。且不改动组件源代码。**

本项目支持 38 种语言，任何文本内容（按钮文字、占位符、标签）都会随语言切换而变化。使用 `getByText()`、`getByRole({ name })`、`getByPlaceholder()` 等文本选择器会导致测试在非英语环境下失败。

**不改源代码**意味着：不添加 `data-testid`、不改组件的 props 或逻辑。完全通过 HTML 已有的属性、结构和语义来定位元素。

## 1. 定位器选择优先级

| 优先级 | 定位方式 | 示例 | 说明 |
|--------|----------|------|------|
| ✅ **首选** | URL 参数（路由自带） | `?openLogin=true` | 弹窗/状态可通过 URL 驱动时，直接绕过 UI 点击 |
| ✅ **首选** | HTML 属性 | `button[type="submit"]`、`input[type="password"]` | 利用 `type`、`aria-*`、`name` 等固有属性 |
| ✅ **首选** | ARIA 角色 | `getByRole('dialog')`、`[role="listbox"]` | 语义角色是标准化的，不依赖语言 |
| ⚠️ **备选** | CSS class 容器 + 子元素 | `.phone-email-input-container input` | 组件特有的容器 class，稳定且不依赖文本 |
| ⚠️ **备选** | DOM 结构 + 唯一属性组合 | `button:not(.btn-square)` | 组合多个特征消除歧义 |
| ❌ **禁用** | `getByText` | `page.getByText('Sign In')` | 文本随语言变化 |
| ❌ **禁用** | `getByRole({ name })` | `page.getByRole('button', { name: 'Sign In' })` | `name` 是文本内容，随语言变化 |
| ❌ **禁用** | `getByPlaceholder` | `page.getByPlaceholder('Password')` | 占位符随语言变化 |
| ❌ **禁用** | `getByLabel` | `page.getByLabel('Email')` | 标签文本随语言变化 |
| ❌ **禁用** | `getByAltText` | `page.getByAltText('logo')` | alt 文本可能国际化 |
| ❌ **禁用** | 自动生成 ID | `page.locator('#modal__r_1_')` | React 自动 ID 每次构建都可能变 |
| ❌ **禁用** | `nth` / `first` / `last` | `page.locator('button').nth(3)` | DOM 顺序变化就会断 |

### 例外情况

仅当测试明确测试某个特定语言的行为时，可以使用文本选择器，但必须通过 `test.use({ locale: 'en-US' })` 锁定语言环境：

```ts
test.use({ locale: 'en-US' });

test('验证英文下登录按钮文案', async ({ page }) => {
  await expect(page.getByRole('button', { name: 'Sign In' })).toBeVisible();
});
```

## 2. 选择器速查表

### 2.1 常见元素定位方式

| 元素 | 推荐选择器 | 原理 |
|------|-----------|------|
| 登录弹窗 | `?openLogin=true` （URL 参数） | 框架自带 URL 驱动弹窗 |
| 注册弹窗 | `?openSignUp=true` （URL 参数） | 同上 |
| 弹窗容器 | `getByRole('dialog')` | 原生 `<dialog>` 语义 |
| 密码输入框 | `input[type="password"]` | HTML 类型属性，唯一 |
| 表单提交按钮 | `button[type="submit"]` | HTML 类型属性，唯一 |
| 手机/邮箱输入框 | `.phone-email-input-container input` | 组件容器 class |
| 国家码选择按钮 | `button[aria-haspopup="listbox"]` | 无障碍属性，唯一 |
| 国家搜索输入框 | `[role="listbox"] input` | 下拉框内部输入框 |
| 国家选项 | `[role="listbox"] [role="option"]` | 搜索过滤后只剩一条时用 `.first()` |
| 清除按钮 | `button[aria-label="Clear input"]` | aria-label 虽含英文但硬编码不翻译 |
| 切换密码可见 | `button[aria-label*="password"]` | 同上 |
| 弹出菜单项 | `[role="menuitem"]` | ARIA 菜单语义 |
| 选项卡 | `[role="tab"]` | ARIA 标签页语义 |
| 错误提示 | `[role="alert"]` | ARIA 警告语义 |
| 关闭按钮 | `button:has(svg.lucide-x)` | 图标特征（注：lucide-x 不翻译） |

### 2.2 弹窗打开方式优先级

1. **URL 参数**：`?openLogin=true` / `?openSignUp=true`（最优先，零 UI 点击）
2. **直接导航**：如果业务有独立登录页，直接 `goto('/login')`
3. **结构点击**：`getByRole('banner').locator('button:not(.btn-square)')` 组合选择器

## 3. 定位策略详解

### 3.1 HTML 属性定位（首选）

利用 HTML 元素本身的属性，这些属性不随国际化变化：

```ts
// 类型属性
page.locator('input[type="password"]')       // 密码输入框
page.locator('button[type="submit"]')         // 提交按钮
page.locator('input[type="checkbox"]')        // 复选框
page.locator('input[type="radio"]')           // 单选框

// 无障碍属性
page.locator('button[aria-haspopup="listbox"]')  // 有下拉框的按钮
page.locator('button[aria-expanded="true"]')     // 已展开的按钮
page.locator('[aria-label="Clear input"]')       // 清除按钮（aria-label 硬编码不翻译）

// 表单属性
page.locator('input[name="username"]')        // 如果组件透传了 name 属性
page.locator('input[required]')               // 必填输入框
page.locator('button[disabled]')              // 禁用按钮
```

### 3.2 ARIA 角色定位（首选）

ARIA 角色是语义化的、标准化的，不受语言影响：

```ts
page.getByRole('dialog')                      // 弹窗
page.getByRole('listbox')                     // 列表选择框
page.getByRole('option')                      // 选项
page.getByRole('tab')                         // 标签页
page.getByRole('tabpanel')                    // 标签面板
page.getByRole('alert')                       // 错误/警告提示
page.getByRole('progressbar')                 // 加载进度
page.getByRole('banner')                      // 顶部导航（<header>）
```

**注意**：只使用 `getByRole('dialog')` 这种不带 `name` 参数的形式，不要传 `{ name: '...' }`。

### 3.3 CSS class 容器定位（备选）

当元素没有唯一的 HTML 属性时，用组件容器 class 缩小范围：

```ts
// 组件有独特的容器 class，通过它找到子元素
page.locator('.phone-email-input-container input')
page.locator('.phone-email-input-container button')

// DaisyUI class 组合
page.getByRole('banner').locator('button.btn-ghost:not(.btn-square)')
```

### 3.4 URL 参数驱动

优先利用框架或业务自带的 URL 参数来打开弹窗、切换状态：

```ts
// 登录/注册弹窗
await page.goto('/main/casino?openLogin=true');
await page.goto('/main/casino?openSignUp=true');

// 钱包弹窗（如果支持）
await page.goto('/main/casino?openFinance=true');
```

### 3.5 搜索后单选

下拉搜索类（如国家选择），先搜索再选唯一结果：

```ts
// 1. 搜索 +86，只剩 China
await page.locator('[role="listbox"] input').fill('86');

// 2. 点唯一选项（不依赖「China」这个文本）
await page.locator('[role="listbox"] [role="option"]').first().click();
```

## 4. 测试代码规范

### 4.1 基本结构

```ts
import { test, expect } from '@playwright/test';

test.use({
  ignoreHTTPSErrors: true,
  viewport: { height: 1200, width: 1880 },
});

test('用户可以使用手机号登录', async ({ page }) => {
  // URL 参数打开弹窗，无需 UI 点击
  await page.goto('/main/casino?openLogin=true');

  // HTML 属性定位
  await page.locator('.phone-email-input-container input').fill('13422323556');
  await page.locator('input[type="password"]').fill('123456');
  await page.locator('button[type="submit"]').click();

  // 断言
  await expect(page.getByRole('dialog')).not.toBeVisible();
});
```

### 4.2 选择器应当"自解释"

选择器本身要能看出选的是什么，方便 review 时判断是否正确：

```ts
// ✅ 好：看到选择器就知道在选什么
page.locator('button[type="submit"]')                    // 提交按钮
page.locator('input[type="password"]')                   // 密码输入框
page.locator('button[aria-haspopup="listbox"]')          // 国家码选择器

// ❌ 差：看不出在选什么
page.locator('div > div > div > button')                  // 深度 DOM 路径
page.locator('span').nth(2)                               // 位置依赖
```

### 4.3 避免硬编码等待

```ts
// ❌ 错误：代码里写死等待时间
await page.waitForTimeout(3000);

// ✅ 正确：等待元素出现
await expect(page.locator('button[type="submit"]')).toBeVisible();

// ✅ 正确：等待网络请求完成
await page.waitForResponse(resp => resp.url().includes('/api/login') && resp.status() === 200);
```

### 4.6 可视化调试（`STEP_DELAY` + 点击高亮）

有头模式下调试时，希望肉眼可见操作过程。通过 `STEP_DELAY` 环境变量控制。**不设值时不停顿、不高亮**，不影响 CI 无头模式。

提供两个工具函数，所有 spec 文件**必须**使用：

```ts
const STEP_DELAY = parseInt(process.env.STEP_DELAY || '0', 10);

/** 步骤间停顿，STEP_DELAY=0 时不产生任何效果 */
const wait = (page: any) => STEP_DELAY > 0 && page.waitForTimeout(STEP_DELAY);

/**
 * Playwright 内置高亮 + 点击
 * - STEP_DELAY > 0：先调用 locator.highlight() 显示红色高亮框，再执行 click
 * - STEP_DELAY = 0：直接 click，无额外开销
 * 替代所有裸 .click() 调用
 */
async function click(locator: any, options?: any) {
  if (STEP_DELAY > 0) await locator.highlight();
  await locator.click(options);
}

test('示例', async ({ page }) => {
  await page.goto('/main/casino');
  await wait(page);                    // STEP_DELAY>0 则等待

  await click(page.locator('button[type="submit"]'));
  await wait(page);                    // 点击后停顿，便于观察结果
});
```

**核心规则**：

| 条件 | `click()` 行为 | `wait()` 行为 |
|------|---------------|---------------|
| `STEP_DELAY=0`（CI/无头） | `locator.click()`，无高亮，零额外开销 | 不等待 |
| `STEP_DELAY=800`（有头调试） | `.highlight()` 红色高亮框 → 停顿 → `.click()` | 每次等 800ms |

**高亮效果**：Playwright 内置 `.highlight()` 在目标元素上叠加一个 **红色半透明边框** 并保持约 2 秒，配合 `STEP_DELAY` 的停顿可以清晰看到每一步点击了哪个元素。

```bash
# 有头模式，每步等 800ms + 点击高亮
STEP_DELAY=800 pnpm test:e2e:headed

# 无头模式，无停顿无高亮
pnpm test:e2e
```

### 4.4 使用相对路径

```ts
// ❌ 错误：硬编码完整 URL
await page.goto('https://localhost:3000/main/casino');

// ✅ 正确：使用相对路径，baseURL 自动拼接
await page.goto('/main/casino');
```

baseURL 由 `playwright.config.ts` 中的 `E2E_BASE_URL` 环境变量控制。

### 4.5 使用注释说明定位原理

复杂的选择器应加注释，说明为什么这样选：

```ts
// 国家码选择按钮：利用 aria-haspopup="listbox" 唯一属性定位
await page.locator('button[aria-haspopup="listbox"]').click();

// 搜索后只剩 +86（中国），用 role 点唯一选项
await page.locator('[role="listbox"] [role="option"]').first().click();
```

## 6. 环境配置

### 可用脚本

| 命令 | 说明 |
|------|------|
| `pnpm test:e2e` | 本地无头模式（默认 `localhost:3000`） |
| `pnpm test:e2e:ui` | 交互式 UI 模式 |
| `pnpm test:e2e:headed` | 有头模式（可见浏览器操作） |
| `pnpm test:e2e:debug` | 调试模式（Playwright Inspector） |
| `pnpm test:e2e:codegen` | 录制模式（生成测试代码） |
| `pnpm test:e2e:report` | 查看测试报告 |
| `pnpm test:e2e:prod` | 对 UAT 环境执行无头测试 |
| `pnpm test:e2e:prod:headed` | 对 UAT 环境执行有头测试 |

### 环境变量

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `E2E_BASE_URL` | `https://localhost:3000` | 测试目标地址 |
| `STEP_DELAY` | `0`（不停顿） | 每步操作后停留毫秒数，有头调试时使用 |

### 配置项目 `playwright.config.ts`

- `baseURL` 通过 `E2E_BASE_URL` 环境变量配置
- 无该环境变量时默认使用 `https://localhost:3000`
- `--base-url` CLI 参数不支持（这不是 Playwright Test 的有效选项）

## 7. 常见反例

### 反例 1：依赖英文文本

```ts
// ❌ 在中文环境中会失败
await page.getByRole('button', { name: 'Sign In' }).click();

// ✅ 用 URL 参数打开弹窗，或通过属性定位
await page.goto('/main/casino?openLogin=true');
// 或在需要点击时：page.getByRole('banner').locator('button:not(.btn-square)').first()
```

### 反例 2：使用 `page.waitForTimeout`

```ts
// ❌ 不稳定的等待
await page.waitForTimeout(5000);

// ✅ 等待特定条件
await expect(page.locator('button[type="submit"]')).toBeVisible();
```

### 反例 3：自动生成的 ID

```ts
// ❌ React 自动 ID 每次构建可能变
page.locator('#modal__r_1_')

// ✅ 用语义角色定位
page.getByRole('dialog')
```

### 反例 4：过度使用 nth

```ts
// ❌ 脆弱的位置依赖
page.locator('button').nth(3).click();

// ✅ 用属性或角色定位
page.locator('button[type="submit"]').click();
```

### 反例 5：硬编码 URL

```ts
// ❌ 只能在 localhost 运行
await page.goto('https://localhost:3000/login');

// ✅ 使用 baseURL 配置
await page.goto('/login');
```

### 反例 6：Codegen 生成的原始测试

```ts
// ❌ Codegen 默认生成大量文本依赖的代码
await page.getByPlaceholder('Email or Phone Number').click();
await page.getByRole('button', { name: 'Selected country: Taiwan' }).click();
await page.getByText('China').click();

// ✅ 改写为语言无关的选择器
await page.locator('.phone-email-input-container input').fill('134');
await page.locator('button[aria-haspopup="listbox"]').click();
await page.locator('[role="listbox"] input').fill('86');
await page.locator('[role="listbox"] [role="option"]').first().click();
```

## 8. Code Review 检查清单

合并 E2E 测试相关的 PR 前，检查以下条目：

- [ ] 无 `getByText`、`getByPlaceholder`、`getByRole({ name })` 等文本依赖
- [ ] 无自动生成 ID（`#modal__r_*` 等）
- [ ] 无 `page.waitForTimeout` 硬编码等待（`STEP_DELAY` 环境变量驱动的等待除外）
- [ ] 使用 `click()` 辅助函数替代裸 `.click()` 调用（已实现高亮+点击，见 §4.6）
- [ ] 组件源代码未被修改（无新增 `data-testid`、无 props 变更）
- [ ] `page.goto()` 使用相对路径
- [ ] 选择器优先使用顺序：URL 参数 → HTML 属性 → ARIA 角色 → CSS 容器 class
- [ ] 无需 `nth()` / `.first()` 也能唯一定位（搜索后单选除外）
- [ ] 复杂选择器有注释说明定位原理
- [ ] 测试描述清晰表达测试意图
- [ ] 测试文件放在 `e2e/` 目录下
- [ ] 测试可以独立运行，不依赖其他测试的状态

---

## 总结

```
优先用 URL 参数驱动 → 其次用 HTML 属性定位 → 再次用 ARIA 角色 → 最后用容器 class
不改组件源代码，不依赖翻译文本
```

**一句话规范**: HTML 已有的属性就是最好的测试选择器，不要为测试改动组件代码。
